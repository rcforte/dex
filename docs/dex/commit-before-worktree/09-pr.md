# Let users commit uncommitted work at the worktree step

## Summary

`/dex:worktree` stopped when the main checkout had uncommitted changes. But the
guard refuses Claude's `git commit` before implementation, so "commit them" could
not be done from Claude. The user was stuck.

Now `/dex:worktree` lists the changes, warns that they will not be in the new
worktree, and offers two choices. The user can continue without them, or commit
them first with a printed line that they run themselves:

```text
! cd "$(git rev-parse --show-toplevel)" && git add -- '<new path>' && git commit -m '<message>' -- '<path>' '<path>'
```

When the guard refuses a `git commit`, its message now names that option too. No
guard decision changed. Plugin version 0.2.2.

The commit line shipped differs from the first version in these documents. Four
rounds of AI review hardened it:
- it adds new files
- it runs from any subfolder
- it uses real names instead of git's quoted form
- it single-quotes names so `$` and backticks survive

`07-implementation-log.md` records each round.

# Let a revised structure add checkpoints mid-implementation

## Summary

Once any checkpoint had started, `set-slices` refused every change to the
checkpoint list. Its error told the user to record design drift. But after the
drift cleared, the same call was refused again. A step added during review
could never be recorded. That is how step S5 of `workflow-launch` ended up
outside Dex's state.

Now the list can change once the user approves a revised structure, provided
that approval is current and newer than the latest checkpoint start:
- New checkpoints can go anywhere in the order.
- Started checkpoints are never dropped, even with `--replace`.
- A checkpoint blocked before it ever started no longer locks the list.
- `set-slices` is refused once the PR is recorded.
- The refusal names the three steps that work: revise the structure, run
  `/dex:approve structure`, then run `set-slices` again.

The implement skill now gives this route for new work found by review. The plan
skill and the README describe the rule. Plugin version 0.2.3.

# Start research and review workflows in any project

## Summary

`/dex:research` and `/dex:review` failed in every project except this repository.
They launched their workflow from the plugin folder, and the Workflow tool only
loads scripts from inside the project.

The skills now run `state.mjs stage-workflow <research|review>` first. It copies
the plugin's workflow to `.dex/_workflows/<name>.js` in the checkout the session
runs in, then prints the path, and the skill launches from that path. The copy is
refreshed on every launch, so the plugin file stays the only source. `.dex/` is
kept out of `git status` by the existing local ignore rule.

`/dex:doctor` now makes the copies for real. It fails when the copy cannot be
written, or when its real path (symlinks followed) is outside the session's
checkout.

Plugin version 0.2.1.

  `dex/tests/LIVE-CHECKS.md` cover the sample project. One is a normal session.
  The other is a session opened in a subfolder, where it is unknown whether the
  Workflow tool accepts a copy at the repository's top level.
- **Doctor now writes to disk.** It writes `.dex/_workflows/` and may add
  `/.dex/` to `.git/info/exclude` in any repository it inspects. This reverses
  part of an earlier fix, on purpose.
